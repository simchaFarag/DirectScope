# DirectScope – אפיון מערכת

> מקור: קובץ Figma ‏`DirectScope` (דף **ready for dev**, סקשן **screens**), כולל הערות המעצבת (דורין שחר).
> עודכן: 18.10.2026

## 1. מה המערכת

אפליקציית מובייל (iPhone 390×844, עברית RTL) לניהול פרויקט בנייה/שיפוץ בין **לקוח (בעל הבית)** לבין **קבלן** ואנשי מקצוע.
הערך המרכזי ללקוח: שקיפות כספית ("כספים מעניינים את הלקוח יותר מהסטטוס"), השוואת הצעות מחיר מול התכנית האדריכלית ומחיר השוק, מעקב לוחות זמנים, תיעוד ואישורי חריגות.

מודל עסקי: מנוי חודשי (₪64 לחודש), כרטיס אשראי.

## 2. משתמשים ותפקידים

| תפקיד | מי | מה רואה / עושה |
|---|---|---|
| **לקוח / משפץ** | בעל הבית שמקים את הפרויקט | הכל: תקציב מלא כולל פירוט עלויות, מאשר עדכונים וחריגות, מזמין שותפים |
| **קבלן** | הקבלן הראשי | רואה **רק את סכום החוזה** (לא את כל התקציב), מעדכן התקדמות, מסמן משימות, שולח בקשות אישור חריגה |
| **אדריכל / מעצב** | בעל מקצוע | מעלה תכניות, מגיב לעדכונים |
| **שותף (משפחה/בעל מקצוע)** | מוזמן ע״י הלקוח בוואטסאפ | הרשאה: **צפייה** או **עריכה** |

### 3.2 שלד האפליקציה

- **App Bar** (עליון): המבורגר ☰ · שם הפרויקט ("פרויקט בנה ביתך") · בדף הבית גם 🔔 התראות ו-👤 פרופיל.
- **Bottom Nav** (תחתון, "glass"): **בית · תקציב · זמנים · ארכיון**.
- **תפריט המבורגר** (מגירה): עדכון אמצעי תשלום · שיתוף אנשי קשר · עזרה טכנית · תנאי שימוש. (מתוכנן לפי ההערות: עריכת פרטים אישיים, הגדרת הרשאות, שינוי סיסמה)

### 3.3 טאב בית

| רכיב | לחיצה מובילה ל- |
|---|---|
| ברכה "בוקר טוב נדב" | – |
| כרטיס **ניהול תקציב** (חצי-עיגול: שולם / סה״כ מעודכן / יתרה) · [הצג עוד] | טאב תקציב |
| **סטטוס פרויקט** (% הושלם, ימים לסיום) | טאב זמנים |
| כרטיס **עדכון יומי** (תמונה, שלב בנייה, משימות, עלות) | מסך עדכונים |
| כרטיסי סטטוס מהירים: "שינוי מחכה לאישורך" / "השלב הושלם בהצלחה" | אישורי חריגה / שלב |
| **מסמכים אחרונים** · [צפייה בגלריה] | ארכיון ← גלריה |

### 3.4 טאב זמנים (לוח זמנים)

- **לשוניות שלבים** בראש: כללי · פירוק · צנרת · חשמל · קרמיקה · תוספות.
- **כללי**: סטטוס פרויקט (%), כרטיס תאריכים (התחלה / סיום משוער / כמה נשאר) ✎, [הוספת שלב], רשימת שלבים עם עיגול התקדמות ואווטארים של בעלי המקצוע ← לחיצה פותחת את לשונית השלב.
- **לשונית שלב**: סטטוס נוכחי (%), תאריכי התחלה/סיום, [עריכת שלב] ← עריכת שלב, **משימות** כ-Timeline (✎ ← עריכת משימות: סימון בוצע, הוספה, עריכה), **עדכונים** (קרוסלה: [אישור] [צפה בעדכון] ← פופאפ עדכון עם תגובות), **תזכורות** (פתקים צבעוניים, לחיצה מגדילה/מקטינה, + ← הוספת תזכורת).

### 3.5 טאב תקציב

- **סקירה**: חצי עיגול "שולמו עד כה", תקציב מעודכן, נותר לתשלום, חריגות שאושרו, [הצג אישורי חריגות ותוספות] ← מסך אישורי חריגה, [הוספת הוצאה] ← הוספת הוצאה; כרטיס לכל שלב (שולמו / יתרה / סה״כ) ↖ ← תקציב שלב.
- **תקציב שלב** (עם לשוניות שלבים): סטטוס תקציב, סה״כ מעודכן, יתרה, סך חריגות, **סכום חוזה קבלן** (נתון נפרד), [עריכת שלב], **רשימת קניות** (צ׳קבוקס, צילום, עריכה, מחיקה), **חריגות לאישור** ([אישור] [צפה בחריגה] ← פופאפ פרטי חריגה), **פירוט הוצאות** (+ ← הוספת אסמכתא: כותרת, סכום, תאריך, קובץ).

### 3.6 טאב ארכיון

לשוניות: **מסמכים · גלריה · אנשים · השראה · תיעוד**; חיפוש, מיון לפי תאריך, סינון, FAB (+).
- מסמכים – מקובצים לפי שלב (היתר הריסה, תכנית אדריכלית, חוזה, הצעת מחיר, מפרט חשמל, תכנית צנרת).
- גלריה – כרטיסי תמונות עם כותרת ותאריך.
- אנשים – אנשי קשר עם תפקיד וטלפון (חיוג).
- השראה – לוח לפי קטגוריות (חדר אמבט, סלון, חלונות, תאורה…).
- תיעוד – עדכונים שאושרו עוברים לכאן (שם, תפקיד, תאריך, שעה, טקסט, שלב).
- לחיצה על מסמך ← **צפייה במסמך** (הורדה / שיתוף). לחיצה על איש קשר ← **כרטיס איש קשר** (חיוג, וואטסאפ, העדכונים שלו). לחיצה על קטגוריית השראה ← **דף הקטגוריה** + הוספת תמונה.
- בתקציב שלב: לחיצה על הוצאה ← **צפייה באסמכתא**. בזמנים: ✎ בכרטיס התאריכים ← **עריכת פרויקט** (שם, כתובת, תאריכים).

### 3.7 עדכונים והתראות (🔔)

- "X ממתינים לאישורך", [הוספת עידכון] ← עדכון חדש (בחירת שלב, תיאור עד 300 תווים, עד 6 תמונות מצלמה/גלריה, [שלח עדכון]).
- כל עדכון: כותב, תפקיד, זמן, שלב, טקסט, תמונה, [אישור] [הוסף הערה] — שרשור תגובות "פינג-פונג" (אין צ׳אט נפרד).
- מחולק: ממתינים לאישור / אושרו.

### 3.8 אישורי חריגה

- **לקוח**: רשימת בקשות (שלב, קבלן, תיאור, סכום) [צפה בחריגה] [אישור] / "חריגה אושרה".
- **קבלן**: אותה רשימה עם "ממתין לאישור", [שליחת אישור חדש] ← טופס: שלב, כותרת, תיאור, תמונות, [שלח בקשה לאישור].

### 3.9 מסכים משניים

עזרה (שאלות נפוצות לפי נושא → פופאפ אקורדיון, וואטסאפ) · תנאי שימוש (צ׳קבוקס + אישור) · אמצעי תשלום (כרטיס, מנוי, חיוב קרוב, [שנה כרטיס] ← פופאפ כרטיס חדש, [ביטול מנוי]).

## 6. פערים / החלטות פתוחות

1. אימות בפועל (SMS OTP) – ספק? (Firebase / Twilio)
2. "השוואת נתונים ובדיקה" של הצעות מחיר – מנוע הניתוח (המעצבת ביקשה להוריד את המילה AI מהקופי).
3. תשלומים – ספק סליקה (Tranzila / Cardcom / Stripe).
4. שליחת הזמנה לשותפים בוואטסאפ – קישור הזמנה / WhatsApp Business API.
5. מסכי קבלן מלאים (מה הקבלן רואה בכל טאב) – בעיצוב קיימים רק מסכי חריגות; שאר המסכים יוצגו לקבלן עם הסתרת נתוני תקציב.
6. מסכים שמוזכרים בהערות ועדיין לא עוצבו: עריכת פרטים אישיים, הגדרת הרשאות, שינוי סיסמה, פופאפ אישור/דחייה.

## 7. התנהגויות צד-לקוח שמומשו

- טפסים משניים נפתחים כ-Bottom Sheet (כמו בפיגמה); בחירת שלב והרשאה – Dropdown עם ✓.
- העלאת תמונות אמיתית (מצלמה / גלריה), כיווץ בצד הלקוח; מסמכים וקבלות – בחירת קובץ.
- אישור / דחייה של עדכון וחריגה בפופאפ אחד (כולל סיבת דחייה). עדכון שאושר → ארכיון "תיעוד" + התמונות לגלריה.
- השלמת משימה עם תיעוד (הערה + תמונה). קבלן שמסמן משימה → נוצר עדכון "ממתין לאישור" ללקוח.
- קרוסלת עדכונים יומיים בדף הבית (מענה ל"איפה רואים עדכונים של ימים קודמים").
- צפייה במסך מלא בתמונות, חיוג / וואטסאפ לאנשי קשר, בחירת איש קשר מהטלפון (Android).
- הודעות אישור (Toast) לכל פעולה, ופופאפ אישור לביטול מנוי.
- PWA: manifest + Service Worker – ניתן להתקין כאפליקציה אחרי העלאה לשרת HTTPS.

## 8. ארכיטקטורה טכנית (שלב 1)

- **Vite + React 18 + TypeScript + Tailwind CSS + React Router**, Mobile-first, `dir="rtl"`.
- נתוני דמו מקומיים (`src/data/mock.ts`) עם state גלובלי (Context) – כך כל הזרימות עובדות מקצה לקצה לפני שיש שרת.
- שלב 2: Backend (Supabase / Firebase: Auth בטלפון, DB, Storage לתמונות ומסמכים) ועטיפה כאפליקציה (Capacitor) ל-iOS/Android.
